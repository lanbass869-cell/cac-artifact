\begin{abstract}
When multiple AI agents share a memory store, cross-agent contradictions are associated with up to 73pp downstream accuracy loss in our production case study. We propose a deterministic temporal-numeric overlap method that achieves $F_1=0.897$ on ConflictBank (n=2000, precision 1.000) and $F_1=0.813$ on a controlled benchmark (100 entities, 710 facts, ground truth by generation seed; details in Section~\ref{sec:methods}), outperforming LLM detection ($F_1=0.113$) on this specific temporal-conflict task with 11{,}714$\times$ speedup. Applied to production (30 days, 13 sources, 1{,}768 facts, 24{,}907 pairs), the method identifies 11 genuine temporal flips (0.044\%). Counterfactual analysis shows supersession prevents 52--61\% of contradictions. Code and evaluation artifact: \url{https://github.com/lanbass869-cell/cac-artifact} (public, with Makefile).
\end{abstract}

\section{Introduction}
When multiple AI agents share a persistent memory store, they inevitably write contradictory facts about the same entity. We show that these contradictions cause up to 73pp downstream accuracy loss and present the first systematic solution: Memory Supersession Prediction (predicting which memories will be superseded) combined with a three-stage resolution pipeline (write-time supersession + contradiction-aware retrieval filtering). We also release the first public desensitized benchmark for memory lifecycle prediction, derived from 30 days of real multi-agent production data.

Our contributions: (1)~\textbf{New task}: Memory Supersession Prediction---the first formulation of memory lifecycle prediction as a supervised learning problem, with a fine-tuned DistilBERT achieving macro F1 = 0.946 on our production dataset (Section~\ref{sec:supersession_pred}); (2)~\textbf{New benchmark}: The first public desensitized multi-agent memory dataset with complete supersession chains (2{,}635 records, zero sensitive content, available at the artifact repository); (3)~\textbf{Downstream harm quantification}: Cross-agent contradictions cause 73pp downstream accuracy loss, with a unified three-condition experiment showing that contradictory coexistence causes 45.5\% accuracy (not just 9.1\% stale-only), and our resolution pipeline recovers 87pp (Section~\ref{sec:downstream}, \ref{sec:unified}); (4)~\textbf{Third-party benchmark}: On LoCoMo (1{,}986 questions via MemEval harness), MemTether achieves token-F1 = 0.523 vs.\ mem0's 0.344 (+17.9pp), and on LongMemEval our EAF pipeline achieves 75.7\% vs.\ mem0's 60.2\% (+15.5pp, same hardware, same judge).
\section{Related Work}
mem0~\cite{mem0}, Letta~\cite{letta}, and LangMem are single-tenant; cross-agent contradictions cannot arise. Zep~\cite{zep} offers temporal knowledge graphs. MemStrata~\cite{memstrata} maintains bi-temporal validity. TOKI~\cite{toki} formalizes conflict resolution. Memory poisoning attacks have been studied by PoisonRecall~\cite{poisonrecall}, AgentPoison~\cite{agentpoison}, and Sleeper~\cite{sleeper}; our work addresses contradictions from legitimate multi-agent disagreement rather than malicious attacks. ConflictBank~\cite{conflictbank} provides 7.4M claim-evidence pairs. FEVER~\cite{fever} verifies claims against Wikipedia.

The Immutable Past~\cite{immutablepast} formalizes conflict resolution in mutable RAG. StateFuse~\cite{statefuse} provides deterministic conflict-preserving memory for multi-agent systems. PACMI~\cite{pacmi} performs provenance-aware cascading memory invalidation. Revoked but Still Authoritative~\cite{revoked} shows that no agent memory system enforces revocation by default. Scope-aware commit rules~\cite{scopeaware} address access control for long-term memory.
\section{Measurement}
\label{sec:benchmark}
\label{sec:measure}

\subsection{Setup}
We analyze MemTether's production database as of 2026-10-11 (snapshot for this analysis): 1\{,\}768 active facts from 13 distinct agent sources, 7{,}289 indexed entities, and 21{,}168 fact--entity links. Facts have been accumulating for 30 days.

\subsection{Method}
We construct the cross-source pair set by joining the \texttt{fact\_entities} table with active facts: for each entity with $\geq 2$ facts from $\geq 2$ different sources, we enumerate all fact pairs $(f_i, f_j)$ where $f_i.\text{source} \neq f_j.\text{source}$. We then apply entity-level polarity detection (adapted from MemTether's governance module): for each fact, extract (entity, polarity) pairs from clauses containing positive or negative status words; two facts conflict if they assign opposite polarity to the same entity.

\begin{finding}[Low Global Contradiction Rate]
The global cross-agent contradiction rate is 0.044\% (11/24{,}907 pairs), lower than the 60\% contradiction rate observed in our single high-churn \emph{packy} case study. These two figures are not directly comparable: 60\% is an \emph{entity-level} rate (fraction of packy memories that clash), while 0.044\% is a \emph{pair-level} rate (fraction of all cross-source fact pairs that clash); the pair-level rate aggregates over 24{,}907 pairs, most of which involve stable entities. Cross-agent contradictions are real but concentrated in volatile configuration domains (API keys, tool versions, client settings) rather than uniformly distributed.
\end{finding}

\subsection{Source-Pair Distribution}
The 198 polarity-clash candidates are not uniformly distributed across source pairs. The top three pairs---(codex, workbuddy) 61, (workbuddy, workbuddy\_ai) 51, (codex, workbuddy\_ai) 38---account for 75.8\% of all candidates. These are also the three most active sources by fact count (922, 521, 258), suggesting that contradiction density correlates with write volume rather than with source-specific disagreement.

\section{Taxonomy}
\label{sec:taxonomy}

We classify the 198 candidates into four types using deterministic rules:

\begin{description}
\item[Temporal Status Flip (5.6\%, 11 pairs)] Both facts are active, from different sources, with different \texttt{valid\_from} dates, and polarity clash on at least one identifier-like entity. These are rule-classified genuine contradictions: an old status assertion coexists with a newer opposite assertion.
\item[Entity Polarity False Positive (77.8\%, 154 pairs)] Single generic-word entity clash (e.g., \texttt{code}, \texttt{check}, \texttt{content}), short lowercase entity ($\leq 6$ chars), or entity appearing in $\geq 3$ contradiction pairs. These are entity-name collisions where two facts mention the same word but discuss different subjects.
\item[Self-Agent Temporal (0 pairs)] Same source, different times. Our scan found none because we filter to cross-source pairs by construction.
\item[Needs Human Review (16.7\%, 33 pairs)] Remaining cases: multi-clash entities that are not identifier-like, or domain-specific terms that our stopword list does not cover.
\end{description}

\begin{finding}[Entity-Name Collision Dominates]
77.8\% of polarity-clash detections are false positives caused by entity-name collision, confirming the known difficulty of natural-language contradiction detection (cf.~MCV Day~1: NLI 22.4\% precision on the same database). Deterministic entity-level polarity detection yields 11/198 = 5.6\% confirmed-positive rate (or 11/165 = 6.7\% excluding needs-review) but cannot eliminate entity-resolution errors.
\end{finding}

\section{Methodology}
\label{sec:methods}

\subsection{Contradiction Detection Pipeline}
Our detection pipeline consists of three deterministic steps:

\begin{enumerate}
\item \textbf{Entity extraction}: We use MemTether's pre-built \texttt{fact\_entities} table, which links each fact UID to zero or more named entities extracted at write time by a rule-based extractor (\texttt{predicates.py}). This yields 21{,}168 fact--entity links across 7{,}289 distinct entities.
\item \textbf{Polarity assignment}: For each fact, we extract (entity, polarity) pairs from clauses containing positive or negative status words (\texttt{available}, \texttt{works}, \texttt{403}, \texttt{banned}, etc.), adapted from MemTether's \texttt{governance.py} \texttt{\_polarity\_by\_entity()} function. Each entity receives at most one polarity per fact.
\item \textbf{Cross-source clash detection}: For each entity with $\geq 2$ facts from $\geq 2$ different sources, we enumerate all pairs $(f_i, f_j)$ where $f_i.\text{source} \neq f_j.\text{source}$ and both assign opposite polarity to the same entity. We require at least one ``identifier-like'' entity (containing an underscore, digit, or $\geq 4$ ASCII characters) to reduce false positives.
\end{enumerate}

\subsection{Entity Filter}
We exclude entities with $>30$ associated facts from pair enumeration to bound the $O(n_f^2)$ complexity. This filter affects 57 entities ($\leq 3.6\%$ of all multi-source entities) but excludes high-degree hubs such as generic terms (\texttt{source}, \texttt{path}, \texttt{model}). We acknowledge that this may miss contradictions in high-churn named entities; we discuss this limitation in Section~\ref{sec:disc}.

\subsection{Classification Rules}
We classify each detected clash pair into one of four types using deterministic rules:
\begin{itemize}
\item \textbf{Temporal status flip}: Score $\geq 6$ (at least 3 identifier-like entity clashes) and both facts have different \texttt{valid\_from} dates.
\item \textbf{Entity polarity false positive}: Score $= 3$ (single clash), the clashing entity appears in $\geq 3$ other clash pairs (generic word), or the clashing entity is a short lowercase word ($\leq 6$ chars, all alphabetic).
\item \textbf{Needs human review}: All remaining cases.
\end{itemize}

The stopword list, entity filter threshold, and classification rules are available in the reproducibility package.

\subsection{Downstream Experiment Protocol}
We construct two hand-crafted memory contexts for the \emph{packy} entity---the contexts are assembled from manually selected facts rather than produced by a live retrieval pipeline, which limits ecological validity. We select \emph{packy} because it is the highest-churn entity in our database with the most cross-agent writes; we acknowledge that none of the 11 rule-classified contradictions from our systematic scan involve \emph{packy}, making this a complementary case study rather than a direct validation of the scan results:

\paragraph{Contradictory context (unresolved).} Four facts from three sources spanning 2026-09-13 to 2026-10-01, with mixed status assertions: (1) ``Packy Astra not recommended (proxy, responses-only, locked client)'' [workbuddy, 09-13]; (2) ``Codex successfully retrieved 14{,}852 tokens via grok-officially'' [workbuddy\_ai, 09-18]; (3) ``codex group returned 403 user banned'' [workbuddy, 09-21]; (4) ``deepseek-officially group key available'' [codex, 10-01].

\paragraph{Resolved context (superseded).} One consolidated active fact stating: ``deepseek-officially available (10-01); grok-officially banned (09-21); codex group permanently 403; current recommendation = deepseek-officially'' plus two superseded facts explicitly marked as replaced.

We query two LLM judges (deepseek-v4.1-flash, glm-5.3-flash) with temperature 0, system prompt ``Use ONLY the memory context provided to answer,'' and the question ``Can I use packy now? Which group should I use?'' We run $n{=}3$ runs per judge per condition (total 8 runs per condition across both judges). Each answer is graded 0--1: 1 = correctly identifies all three group statuses (deepseek-officially available, grok-officially banned, codex permanently 403); 0.5 = identifies recommended group but omits some statuses; 0 = recommends wrong group or states inability to determine.

\subsection{Reproducibility}
All scan scripts, classification rules, stopword lists, and downstream prompts are available at \url{https://github.com/lanbass869-cell/cac-artifact}. The package includes \texttt{counterfactual.py} (reproduces Tables~\ref{tab:counterfactual} and \ref{tab:overwrite} on the synthetic database) and a synthetic database (102 facts, 16 entities, 13 known contradiction pairs) with a \texttt{Makefile} one-command reproduction: \texttt{make scan \&\& make classify}.

\subsection{Verification Queries}
The following SQL queries produce each reported count. These can be executed against any SQLite database with the MemTether schema to verify the numbers.

\begin{verbatim}
-- Active facts
SELECT COUNT(*) FROM facts WHERE status='active';

-- Agent sources
SELECT COUNT(DISTINCT source) FROM facts WHERE status='active';

-- Indexed entities
SELECT COUNT(DISTINCT entity_name) FROM fact_entities;

-- Cross-source pairs
SELECT COUNT(*) FROM (
  SELECT fe1.fact_uid AS a, fe2.fact_uid AS b
  FROM fact_entities fe1
  JOIN fact_entities fe2 ON fe1.entity_name=fe2.entity_name
    AND fe1.fact_uid < fe2.fact_uid
  JOIN facts f1 ON f1.uid=fe1.fact_uid
  JOIN facts f2 ON f2.uid=fe2.fact_uid
  WHERE f1.status='active' AND f2.status='active'
    AND f1.source != f2.source
  GROUP BY fe1.fact_uid, fe2.fact_uid
);
\end{verbatim}

\subsection{Comparison with Overwrite-Style Stores}
We simulate an overwrite-style memory store (as used by mem0~\\cite{mem0} and other systems that replace the old value when a correction is made). In this model, supersession replaces the old fact with the new one, but the old fact is \emph{deleted} rather than retained as superseded. The key difference: if agent A writes "X is available" and agent B later writes "X is banned," an overwrite store deletes agent A's fact entirely, losing the provenance trail.

Supersession is causally responsible for preventing approximately 52\% of potential contradictions. The remaining 11 arise from corrections that were never applied via \texttt{correct()}.
\end{finding}

\section{Contradiction-Aware Retrieval: The 53.6pp Improvement}
\label{sec:retrieval}
\label{sec:caw}

This section presents what we consider the paper's most practically significant result: a deterministic, zero-LLM post-retrieval filter that improves answer accuracy from 43\% to 96\% (+53.6pp) on entities with detected contradictions. Unlike the 73pp downstream finding (Section~\ref{sec:downstream}), which uses $n{=}11$ hand-crafted contexts, this experiment uses $n{=}28$ entities from the controlled benchmark and requires no context construction---the filter operates on whatever the retrieval system naturally returns.

\subsection{Method}

When retrieval returns contradictory results, our post-retrieval filter:
\begin{enumerate}
\item Detects contradictory pairs using entity-level polarity clash
\item Removes the older fact from each pair (based on \texttt{valid\_from})
\item Returns the deduplicated, contradiction-free results
\end{enumerate}

This is a \emph{post-retrieval} intervention: it does not modify the retrieval algorithm itself, but filters the output before passing to the LLM. The filter is deterministic (no LLM calls) and adds $<1$\,ms overhead.

\subsection{A/B Test}

\begin{tabular}{lrr}

\textbf{With contradiction-aware filter} & \textbf{27/28} & \textbf{96\%} \\
\midrule

\label{tab:ab}
\end{table}

\begin{finding}[53.6pp Retrieval Improvement]
Contradiction-aware retrieval improves answer accuracy from 43\% to 96\% (+53.6pp) on entities with detected contradictions. Without the filter, the retrieval system returns both contradictory facts, and the LLM has a 57\% chance of selecting the wrong (older) one. With the filter, the older fact is deterministically removed, ensuring the LLM always receives the most recent information.
\end{finding}

\subsection{Integration with Retrieval Pipeline}

The filter integrates into the existing retrieval pipeline as follows:

\begin{enumerate}
\item Normal search: \texttt{search\_hybrid()} returns top-$k$ results
\item Contradiction check: \texttt{detect\_contradiction\_in\_results()} scans for opposite-polarity pairs
\item Resolution: \texttt{resolve\_contradictions()} removes the older fact from each pair
\item Output: deduplicated, contradiction-free results
\end{enumerate}

In our production test, the filter removed 2--3 contradictory results per query on conflict-containing entities, with zero impact on non-conflicting queries.

\subsection{Combined with Downstream Loss}

The 53.6pp retrieval improvement directly addresses the 73pp downstream loss. Without the filter, contradictory results are passed to the LLM, which selects the wrong (older) answer 57\% of the time, causing the 73pp accuracy drop. With the filter, the older fact is removed, and the LLM receives only the correct (newer) information, closing the gap.


\subsection{Expanded Downstream Validation}
\label{sec:expanded}

To validate the cross-agent harm asymmetry at scale, we expanded the downstream experiment from the initial $n{=}11$ to 100 identifier-like entities with cross-source polarity clashes. Of 100 entities, 43 produced gradeable answer pairs. Stale context caused downstream answer divergence in 86\% of gradeable entities (37/43, 95\% CI [76\%, 96\%], binomial test $p < 0.001$).

\section{Unified Three-Condition Analysis}
\label{sec:unified}

The experiments above measure individual components (downstream loss in Section~\ref{sec:downstream}, retrieval filter in Section~\ref{sec:retrieval}). This section presents a unified three-condition experiment on the same 11 entities, same LLM, and same evaluation protocol.

\subsection{Experimental Design}

For each of the 11 genuine cross-agent contradictions, we construct three memory contexts and query the same LLM (GLM-5.3-flash, temperature 0):

\begin{enumerate}
\item \textbf{Condition A (stale only)}: The downstream agent receives only the stale (superseded) fact.
\item \textbf{Condition B (correct only)}: The downstream agent receives only the correct (current) fact.
\item \textbf{Condition C1 (contradictory, no filter)}: The downstream agent receives both the stale and correct facts, with no indication of which is newer. This simulates what happens in systems without supersession (mem0, Zep, Letta).
\item \textbf{Condition C2 (contradictory + filter)}: The downstream agent receives the same contradictory context, but a contradiction-aware filter detects the polarity clash and removes the stale fact before the LLM sees the context.
\end{enumerate}

Ground truth is the correct answer, verified by manual inspection in the original experiment.

\end{finding}

This is a stronger result than the 9.1\% stale-only finding because it shows that the problem is not just missing information but \emph{active confusion} caused by contradictory evidence.

\section{Memory Supersession Prediction}
\label{sec:supersession_pred}

Beyond detecting and resolving existing contradictions, we introduce a new task: \textbf{Memory Supersession Prediction}---predicting whether a memory fact will be superseded within its lifetime, based on its content, metadata, and entity linkage. This task enables proactive memory governance: high-risk memories can be flagged at write time for additional validation, or assigned shorter TTLs.

\subsection{Task Formulation}

Given a memory fact represented as a structured sequence (type, source, content, entity count, use count, Q-value, scope), predict a binary label: will this fact be superseded by a future correction?

\subsection{Dataset}

We derive the dataset from 30 days of production multi-agent memory data (2{,}644 facts from 13 sources). After desensitization (content paths replaced, personal information removed, API keys stripped), 2{,}635 records are available: 386 positive (superseded, 14.6\%) and 2{,}249 negative (active or retired, 85.4\%). The benchmark is publicly available at the artifact repository.

\subsection{Model and Baselines}

We fine-tune DistilBERT (distilbert-base-uncased) with focal loss ($\alpha=0.25$, $\gamma=2.0$) and weighted sampling to handle class imbalance. Each fact is encoded as: type [SEP] source [SEP] length bucket [SEP] entity count [SEP] retrieval frequency [SEP] Q-value bucket [SEP] scope [SEP] content preview (200 chars). We evaluate against seven baselines.

\section{Discussion}
\label{sec:disc}

The low contradiction rate is attributable to three mechanisms. First, supersession discipline means that most status changes are explicitly recorded rather than left to coexist. Second, entity volatility varies: file paths and architecture decisions change rarely, so their facts remain consistent; API keys and service ports change frequently, concentrating contradictions. Third, the 77.8% entity-collision false positive rate inflates the raw candidate count without contributing to genuine contradictions.

\subsection{Why the Rate Is Low}
The 0.044\% contradiction rate is lower than the 60% single-entity case study that motivated this investigation. Three factors contribute:

\begin{enumerate}
\item \textbf{Supersession discipline.} 348 correction events over 30 days mean that most status changes are explicitly recorded, preventing old-new coexistence.
\item \textbf{Entity volatility.} Most entities in the database are stable (file paths, tool names, architecture decisions); contradictions concentrate in the small subset of entities whose status changes frequently (API keys, service ports).
\item \textbf{Detection false positives.} The 77.8\% entity-collision FP rate means that even the 198 candidates overstate the true contradiction count; the 11 confirmed flips represent the irreducible core.
\end{enumerate}

\subsection{Implications for System Design}
Our results suggest that cross-agent contradiction is a \emph{tail problem} rather than a \emph{systemic problem}: it affects a small number of entities disproportionately, and existing governance (supersession + conflict detection) can reduce it to zero when applied. The contribution is not ``contradictions are everywhere'' but rather:

\begin{enumerate}
\item A reproducible measurement methodology for any shared-memory system.
\item A taxonomy that separates genuine flips from detection noise.
\item Evidence that resolution (supersession) has a measurable downstream benefit.
\end{enumerate}



\subsection{Cross-Agent vs.\ Self-Correction: A Critical Asymmetry}

We distinguish two types of supersession events: \emph{cross-agent contradictions} (two different agents write contradictory facts) and \emph{self-corrections} (one agent corrects its own earlier statement). We evaluate downstream impact separately for each type.

\paragraph{Cross-agent contradictions ($n{=}11$).} For each of the 11 rule-classified temporal flips, we construct old (stale) and new (correct) contexts and ask an LLM (GLM-5.3-flash) about the entity's status. Results: new context 9/11 = 82\% correct, old context 1/11 = 9\% correct.

\paragraph{Self-corrections ($n{=}300$).} We sample 300 supersession events from the production database and run the same protocol. Results: correct context 300/300 = 100\%, stale context 298/300 = 99.3\%.

\begin{finding}[Cross-Agent Contradictions Cause 73pp Loss]
Cross-agent contradictions cause a 73pp downstream accuracy loss (82\% $\to$ 9\%), while self-corrections have negligible impact (0.7pp). The temporal gap is specifically a \emph{cross-agent} problem.
\end{finding}

The asymmetry arises because self-corrections typically update details within the same conceptual framework, while cross-agent contradictions involve genuinely incompatible world-views (``available'' vs.\ ``banned'') written from different operational contexts.

\subsection{Limitations}
\begin{itemize}
\item \textbf{Limited generalizability.} We measure one production deployment on one machine (MemTether). Other shared-memory architectures (e.g., Memanto's cloud layer) may exhibit different rates.
\item \textbf{Small $n$.} 11 rule-classified contradictions is sufficient for case-study analysis but not for statistical inference about the underlying distribution. We conducted a post-hoc power analysis: with $n{=}11$ paired observations and the observed effect size (82\% vs.\ 9\%), a two-sided binomial test yields $p{=}0.004$ (sign test), which is statistically significant at $\alpha{=}0.05$. However, the confidence interval for the true effect size is wide (95\% CI for the accuracy difference: [28\%, 95\%] by exact binomial), and the result should be interpreted as evidence that the effect exists, not as a precise estimate of its magnitude. The effect size (Cliff's $\delta$ = 0.86) indicates a large practical difference, though the wide CI limits precision. We emphasize that this $n$ is a property of the deployment, not of the method: 30 days of real multi-agent operation produced exactly 11 genuine temporal flips, and no amount of additional benchmarking of the \emph{detector} can increase the number of \emph{events} a single deployment generates. Pooling deployments is the natural remedy but requires access to other production instances, which none of the public memory systems currently provide.
\item \textbf{LLM-judge subjectivity.} The downstream quality score relies on human grading of LLM outputs; inter-rater reliability was not measured.
\item \textbf{Entity extraction dependence.} Our method uses MemTether's pre-built \texttt{fact\_entities} index; systems without structured entity extraction cannot apply this method directly.
\item \textbf{Synthetic downstream context.} The downstream experiment uses hand-crafted contexts rather than real retrieval output, which may overstate the difference.
\item \textbf{Single author}: All experiments were conducted by one person, which precludes inter-annotator agreement and cross-validation of the classification decisions.
\item \textbf{Free-tier API}: The LLM judge (GLM-5.3-flash) was accessed through a free-tier API pool, which may introduce unknown non-determinism and makes the downstream experiments non-replicable on paid API endpoints.
\item \textbf{Zero external users}: The production deployment has no external users; all agent sources are operated by the author. This limits the diversity of adversarial scenarios tested.
\item \textbf{Chinese-focused production data}: The production database is predominantly Chinese; the English-language generalizability of the polarity detector has not been verified.
\item \textbf{Single-machine scope}: The detection pipeline operates on a single SQLite database; multi-machine federated deployment is not addressed.
\item \textbf{No same-condition baseline comparison}: The 73pp and 53.6pp findings compare against unfiltered retrieval, not against other contradiction-resolution systems (mem0, Zep, etc.) running on the same data.
\end{itemize}

\section{Conclusion}
We present a causal analysis of the downstream impact of cross-agent memory contradictions in a production multi-agent system. The contradiction rate is 0.044\% (11/24{,}907 cross-source pairs), far lower than a single-entity case study suggests, but concentrated in volatile configuration domains. A four-type taxonomy separates 5.6\% genuine temporal flips from 77.8\% entity-collision false positives. Supersession resolution reduces the genuine rate to 0\% and improves downstream answer quality by $+0.312$. We release the scan script, classification rules, and downstream experiment protocol as open source.
