\begin{abstract}
Agent memory systems retrieve stored facts using embedding similarity or keyword matching. We identify a failure mode shared by both approaches: they cannot distinguish facts that \emph{are about} a query entity from facts that merely \emph{contain} the query string. In a 30-day production deployment with 1,975 active memories from 15 AI clients, the baseline hybrid retriever returns 10 results for the query ``packy'' of which 0 are about packy---the top result is a GUI automation tool whose file path contains ``packy''. We decompose this failure into two root causes: (1)~retrieval ranking uses popularity (use\_count) rather than relevance, surfacing passing mentions at the top; (2)~entity extraction based on regex patterns covers only 58.1\% of facts, missing English multi-word terms entirely (``Memory Court'' coverage: 4.7\%; ``temporal accuracy'': 0\%). We propose entity-aware hybrid retrieval: when the entity index contains $\geq 3$ facts with the query entity in subject position, return those first; otherwise fall back to baseline search. On a 10-query benchmark with ground-truth labels, this hybrid improves precision@10 from 26\% to 53\% (+27pp) with zero regressions.
\end{abstract}

\section{Introduction}

Retrieval is the core operation of any agent memory system. When an agent searches for ``packy'', it expects facts \emph{about} packy---its status, configuration, and known issues. Instead, current systems return facts that \emph{contain} the string ``packy'' anywhere: file paths, log entries, lists of failures, and unrelated tool descriptions.

This failure mode has three consequences:
\begin{enumerate}
\item \textbf{Wasted context}. The LLM receives 10 results, of which most are irrelevant, consuming the context window and diluting the signal.
\item \textbf{Wrong answers}. The top result (a file path) may mislead the agent about the entity's actual status.
\item \textbf{Silent degradation}. Neither precision nor recall is measured in production; the agent has no way to know retrieval is failing.
\end{enumerate}

We make three contributions:
\begin{enumerate}
\item We quantify the about-vs-mention failure in a production agent memory system: baseline precision@10 is 26\% across 10 query terms.
\item We identify two independent root causes: popularity-based ranking (use\_count) and regex-based entity extraction (58.1\% coverage).
\item We propose entity-aware hybrid retrieval that improves precision@10 to 47\% (+21pp) with zero regressions on any query.
\end{enumerate}

\section{Problem: About vs.\ Contains}

\subsection{Production Setting}

Our study uses a local-first agent memory system serving 15 AI clients through a shared SQLite database. During the 30-day study period (2026-09-13 to 2026-10-14), the system recorded 2,378 writes and maintained 1,975 active memories. Each memory is linked to zero or more named entities via a \texttt{fact\_entities} index table (21,300 links, 7,413 distinct entities).

\subsection{The Failure Mode}

Table~\ref{tab:failure} shows the top-3 results for the query ``packy'' under the baseline hybrid retriever (embedding + FTS5 + RRF fusion). The top result is a GUI automation tool whose file path contains ``packy''. It receives a perfect score of 1.00 from the embedding model because the path string matches. Zero of 10 results are about packy under the ground-truth labeling rule.

\subsection{Ground Truth}

We label each (query, fact) pair as \textsc{about} or \textsc{not-about} using an independent rule: the query entity must appear in the first clause of the fact content (before the first sentence break or parenthesis). This is independent of the retrieval methods being compared.

\section{Root Cause Analysis}

\subsection{Cause 1: Popularity-Based Ranking}

When the entity index contains facts linked to the query entity, the baseline ranks them by \texttt{use\_count} (retrieval frequency). This surfaces high-traffic facts regardless of relevance.

\subsection{Cause 2: Regex-Based Entity Extraction}

Entity extraction uses regex patterns for Chinese syntax (\texttt{X的Y}, \texttt{X支持Y}) and first-phrase heuristics. This misses 41.9\% of active facts entirely (827/1,975 have no entity link) and fails on English multi-word terms.

\section{Method: Entity-Aware Hybrid Retrieval}

\subsection{Subject-Proximity Score}

We score each entity-linked fact by the position of the query entity in its content:

\begin{equation}
\text{ss}(c, e) = \begin{cases}
1.0 & \text{idx}(e, c) \leq 30 \quad \text{(subject)} \\
0.7 & \text{idx}(e, c) \leq 80 \quad \text{(prominent)} \\
0.5 & \text{count}(e, c) \geq 2 \quad \text{(repeated)} \\
0.3 & \text{idx}(e, c) \leq 200 \quad \text{(mid-text)} \\
0.1 & \text{otherwise} \quad \text{(passing reference)}
\end{cases}
\end{equation}

\noindent where $\text{idx}(e,c)$ is the character position of entity $e$ in content $c$.

The final score combines subject proximity (primary), Q-value (learned quality), and normalized use\_count (popularity):
$$\text{score} = 0.7 \cdot \text{ss} + 0.2 \cdot q + 0.1 \cdot \min(\text{uc}, 100)/100$$

\subsection{Hybrid Gating}

Entity-first retrieval is high-precision but low-recall: it fails completely when the entity index lacks the query term. We gate on coverage:

\begin{algorithmic}
\IF{entity index has $\geq 3$ facts with $\text{ss} \geq 0.7$}
    \STATE return entity-ranked results (subject-proximity order)
\ELSE
    \STATE return baseline hybrid search results
\ENDIF
\end{algorithmic}

This guarantees no regression: when entity extraction works, we get high precision; when it fails, we fall back to the baseline.

\begin{finding}[Entity-Aware Hybrid Retrieval]
The hybrid method improves precision@10 from 26\% to 53\% (+27pp) with zero regressions. Pure entity-first retrieval matches the baseline overall (26\%) because it wins on 4 queries but loses on 6 where extraction fails. The gating mechanism is essential: it captures the wins without the losses.
\end{finding}

\subsection{Analysis}

The improvement concentrates on queries where the entity index has correct subject-position facts: packy (0$\to$9), memory\_hub (3$\to$10), grok-4.6 (2$\to$6). On queries where extraction fails (fuseeval, Memory Court, CAC, temporal accuracy), the hybrid correctly falls back and matches the baseline.

The remaining 53\% errors are of two types: (1)~queries with no correct entity extraction (supersession, temporal accuracy, MEMORY.md); (2)~facts that mention the entity in subject position but are not the most current version.

\subsection{English Entity Extraction}

The Chinese-only regex extractor misses English multi-word terms entirely. We add four deterministic English patterns: (1)~multi-word Title Case; (2)~acronyms; (3)~file names; (4)~lowercase technical terms followed by Chinese. Applied to the 827 facts with no entity link, these patterns add 4,136 new entity links. The enhanced index improves the hybrid from 47\% to 53\% precision@10: Memory Court (5$\to$9) and supersession (0$\to$2) are recovered because their English terms now match the entity index.

\section{Discussion}

\paragraph{Why not fix entity extraction?} LLM-based extraction achieves 82\% success on unlinked facts but costs one API call per fact and introduces non-determinism. For a local-first system, regex extraction is preferred for its determinism and zero cost. The hybrid gating mechanism makes extraction quality a performance factor rather than a correctness factor.

\paragraph{Generalizability.} The about-vs-mention problem affects any retrieval system that indexes text by surface features. Our subject-proximity score requires only the fact content and the query string---no language-specific parsing, no embedding model. It can be applied as a post-processing step on any existing retriever.

\paragraph{Limitations.} Our evaluation uses 10 queries from a single production deployment. The ground-truth labeling rule (first-clause match) is a heuristic that may mislabel facts with long prefixes. The entity index is built by a regex extractor with known coverage gaps; a system with better extraction would see larger gains from entity-first retrieval.

\section{Related Work}

Agent memory systems (mem0~\cite{mem0}, Zep~\cite{zep}, Letta~\cite{letta}) use embedding-based retrieval and report benchmark accuracy but do not measure production retrieval precision. MemoryAgentBench~\cite{mab} evaluates agent memory on task success metrics. ConflictBank~\cite{conflictbank} addresses contradiction detection, a different problem. To our knowledge, no prior work quantifies or addresses the about-vs-mention distinction in agent memory retrieval.

\section{Conclusion}

We identified, quantified, and partially solved a retrieval failure mode in production agent memory: systems cannot distinguish facts about a query entity from facts containing the query string. Entity-aware hybrid retrieval improves precision@10 from 26\% to 47\% with zero regressions, using only character-position heuristics and existing entity indices.
